# نیروکار | NirooKar

بازارگاه چندخدمتی خدمات فنی، نصب و فروشگاه‌های مرتبط — **پیش‌انتشار فاز ۱** (`0.1.0`، بیلد `001`).

> **قانون طلایی فاز ۱:** فقط صفحه اول، سه مسیر ورود مشتری/نصاب/فروشگاه، ساختار اولیه
> پنل مدیریت و اپ موبایل با همین محدوده ساخته شده است. هیچ قابلیت دیگری پیاده‌سازی
> نشده و هیچ دکمه‌ای قابلیت جعلی را شبیه‌سازی نمی‌کند؛ هر بخش غیرفعال، صادقانه
> «فعال‌نشده» را اعلام می‌کند و داده‌های نمایشی با برچسب «Demo» مشخص‌اند.

## ۱) سه محصول پروژه (Monorepo)

| محصول | مسیر | فناوری | وضعیت فاز ۱ |
|---|---|---|---|
| **وب‌سایت + پنل مدیریت** | `src/` (نگاشت فعلی apps/web) | Next.js 16 · React · TypeScript | ✅ فعال — پیش‌نمایش زنده |
| **اپ موبایل** | `apps/mobile/` | Expo · React Native · TypeScript | ✅ کد کامل — ساخت APK در CI |
| **Backend آینده** | `apps/api/` | Node.js · TS (NestJS فقط گزینه) | ⚠️ فقط ساختار و مرزها — غیرعملیاتی |
| **کد مشترک** | `packages/shared/` | TypeScript خالص | ✅ نقش‌ها، RBAC، اعتبارسنجی، ماتریس |
| **تنظیمات مشترک** | `packages/config/` | tsconfig پایه · env.example | ✅ |
| اپ Flutter (میراث مشخصات قبلی) | `flutter_app/` | Flutter · Dart | ❄️ منجمد — بدون توسعه (بخش ۶ معماری) |

**مستندات کامل:** `docs/ARCHITECTURE.md` · `docs/FEATURE_PARITY_MATRIX.md` · `docs/ROADMAP.md` · `docs/VERSIONING.md`

## ۲) وب‌سایت (پیش‌نمایش زنده)

تمام نماها روی مسیر `/` با ناوبری hash اجرا می‌شوند و دکمه بازگشت مرورگر کار می‌کند:

| مسیر | توضیح |
|---|---|
| `#/` | خانه — سه ورودی متمایز مشتری / نصاب / فروشگاه (واکنش‌گرا برای موبایل تا دسکتاپ) |
| `#/login/customer` | فرم ورود مشتری با اعتبارسنجی |
| `#/login/installer` · `#/login/shop` | فرم‌های ورود نصاب و فروشگاه |
| `#/guide` · `#/about` | راهنما و درباره ما |
| `#/status` | **وضعیت توسعه + ماتریس تطبیق امکانات** (شفافیت کامل) |
| `#/admin` | **پنل مدیریت** — ورود نمایشی، داشبورد، ۹ منو، ماتریس RBAC |

- اعتبارسنجی: موبایل `09xxxxxxxxx`، ایمیل، رمز ≥۶ کاراکتر، نرمال‌سازی ارقام فارسی
- لایه Repository با قرارداد مشخص (`AuthRepository`) — آماده اتصال بک‌اند بدون بازنویسی UI
- طراحی از طرح مرجع: برند نیروکار (سبزآبی/سرمه‌ای/مرجانی)، فونت وزیرمتن، RTL

## ۳) اپ موبایل (Expo / React Native)

همان صفحات فاز ۱ به‌صورت اپ بومی: صفحه آغازین با سه نقش، فرم‌های ورود با اعتبارسنجی
مشترک، راهنما و درباره ما — RTL فارسی با `I18nManager`.

```bash
cd apps/mobile
npm install
npx expo start
```

ساخت APK: `docs/VERSIONING.md` — خودکار با GitHub Actions (Artifact) یا محلی با gradle.

## ۴) پنل مدیریت (فاز ۱ = ساختار و طراحی اولیه)

- ورود **نمایشی** با انتخاب نقش (مدیر کل، عملیات، مالی، پشتیبانی، بازرس) برای نمایش
  واقعی معماری RBAC — احراز هویت واقعی فقط در فاز Backend
- ۹ بخش: داشبورد، کاربران، فروشگاه‌ها، نصاب‌ها، سفارش‌ها، مالی، شکایات و تخلفات،
  گزارش‌ها، تنظیمات
- همه داده‌ها «نمایشی» برچسب‌دار؛ نمونه طراحی تاریخچه Append-Only سفارش‌ها (پایه
  پیگیری زنده فاز ۲) در بخش سفارش‌ها پیاده شده است
- کنترل دسترسی واقعی باید سمت سرور اجرا شود — مخفی‌کردن منو فقط نمایش معماری است

## ۵) فاز ۱ — چه چیزی انجام شده / نشده

**انجام‌شده:**
- ساختار ماژولار وب + موبایل + پکیج مشترک با جداسازی UI / منطق / مدل / لایه سرویس
- هویت بصری متمرکز (رنگ‌ها، فونت وزیرمتن، فاصله‌ها) + طراحی واکنش‌گرا دسکتاپ/تبلت/موبایل
- سه مسیر ورود با فرم‌های اعتبارسنجی‌شده و ناوبری واقعی
- ساختار اولیه پنل مدیریت + RBAC + صفحه وضعیت توسعه
- اپ Expo با همان محدوده + CI دوپلتفرمه (کیفیت وب + APK موبایل)
- مستندات کامل: معماری، ماتریس امکانات، نقشه راه، نسخه‌بندی، امنیت
- تست‌های Flutter میراث حفظ شده است (`flutter_app/test`)

**عمداً انجام‌نشده (نیازمند تأیید مالک برای فازهای بعد):**
- Backend عملیاتی، احراز هویت واقعی، ثبت‌نام، فراموشی رمز
- سفارش، پیگیری زنده، چت، پرداخت، کمیسیون واقعی، اعلان‌ها
- رسیدگی عملیاتی به شکایت/خسارت و هر سازوکار حقوقی/مالی
- هر دسته‌بندی خدماتی (فقط در «راهنما» به‌عنوان نقشه آینده)

## ۶) اجرای محلی

### وب (Next.js)
```bash

bun run lint       # ESLint
bunx tsc --noEmit  # بررسی تایپ
```

### موبایل (Expo)
```bash
cd apps/mobile && npm install && npx expo start
```

### Flutter (میراث — منجمد)
```bash
cd flutter_app
flutter pub get && flutter test && flutter analyze
```

## ۷) نسخه‌بندی

- **نسخه محصول:** جاری `0.1.0` (پیش‌انتشار) — نسخه رسمی `1.0.0` فقط برای اولین انتشار
  عمومی نهایی رزروشده است (`packages/shared/src/version-core.ts`).
- **شماره Build:** مستقل از نسخه؛ در CI برابر `github.run_number` و افزایشی
  (001، 002، …). `versionCode` اندروید نیز افزایشی است.
- جزئیات کامل: `docs/VERSIONING.md`.

## ۸) GitHub Actions

| Workflow | محرک | جاب‌ها |
|---|---|---|
| `ci.yml` | push/PR | کیفیت وب (lint + tsc + build) · تایپ موبایل · **ساخت APK + Artifact** |
| `flutter-apk.yml` (میراث) | push در `flutter_app/**` | تحلیل + تست + APK Flutter |

**دریافت APK موبایل:** مخزن → تب Actions → اجرای موفق «CI» → Artifacts →
`nirookar-mobile-apk-build-<N>`.

## ۹) امنیت

- هیچ کلید/توکن محرمانه‌ای در کد یا این مخزن قرار ندارد (ببینید `SECURITY.md`).
- اطلاعات حساس فقط از طریق **GitHub Secrets** به CI تزریق می‌شود.
- `.env*` در `.gitignore` است و نباید commit شود؛ الگو: `packages/config/env.example`.
- مرز نقش‌ها از ابتدا در مدل داده و رجیستری نقش‌ها لحاظ شده است.
- در فاز ۱ هیچ داده کاربری جمع‌آوری یا ارسال نمی‌شود.

## ۱۰) پیش‌نمایش زنده وب
