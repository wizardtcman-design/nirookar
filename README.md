# نیروکار | NirooKar

بازارگاه چندخدمتی خدمات فنی، نصب و فروشگاه‌های مرتبط — **فاز ۲ گام ۱** (`0.1.1`، بیلد `002`).

> **وضعیت فعلی:** ورود و ثبت‌نام واقعی با OTP آزمایشی (Sandbox — کد `12345`)، پنل مدیریت
> متصل به دیتابیس با کنترل دسترسی سمت سرور، تنظیمات پویای کامل (قانون «صفر درصد هاردکد»).
> هیچ دکمه‌ای قابلیت جعلی را شبیه‌سازی نمی‌کند؛ هر بخش غیرفعال صادقانه «فعال‌نشده» را
> اعلام می‌کند و داده‌های نمایشی باقی‌مانده با برچسب «Demo» مشخص‌اند.

## ۲) وب‌سایت (پیش‌نمایش زنده)

تمام نماها روی مسیر `/` با ناوبری hash اجرا می‌شوند و دکمه بازگشت مرورگر کار می‌کند:

| مسیر | توضیح |
|---|---|
| `#/` | خانه — سه ورودی متمایز مشتری / نصاب / فروشگاه (بدون لینک عمومی ادمین) |
| `#/login/customer` | ورود/ثبت‌نام مشتری با OTP |
| `#/login/installer` · `#/login/shop` | ورود/ثبت‌نام نصاب و فروشگاه — پرونده کامل (کد ملی، شبا، عکس الزامی) |
| `#/guide` · `#/about` | راهنما و درباره ما |
| `#/status` | **وضعیت توسعه + ماتریس تطبیق امکانات** (شفافیت کامل) |
| `#/admin` | **پنل مدیریت** — ورود واقعی با OTP فقط برای نقش‌های مدیریتی |

- ورود با OTP آزمایشی (کد `12345` — Sandbox) + نشست کوکی امن httpOnly
- لینک پنل مدیریت عمومی نیست؛ مدیر لاگین‌شده دکمه طلایی «اتاق فرمان / مدیریت» می‌بیند
- سوییچر سریع نمایشی (فلش آزمایشگاهی گوشه صفحه) برای تست راحت مالک

## ۳) اپ موبایل (Expo / React Native)

صفحات فاز ۱ به‌صورت اپ بومی: صفحه آغازین با سه نقش، فرم‌های ورود با اعتبارسنجی
مشترک، راهنما و درباره ما — RTL فارسی با `I18nManager`. گام بعدی: اتصال به همان
API ورود/ثبت‌نام پس از استقرار endpoint عمومی.

```bash
cd apps/mobile
npm install
npx expo start
```

ساخت APK: `docs/VERSIONING.md` — خودکار با GitHub Actions (Artifact) یا محلی با gradle.

## ۴) پنل مدیریت (فاز ۲ گام ۱ — متصل به دیتابیس)

- ورود واقعی با OTP (Sandbox) — فقط نقش‌های مدیریتی؛ دسترسی غیرمدیر پیام صادقانه می‌گیرد
- ۹ بخش: داشبورد، کاربران، فروشگاه‌ها، نصاب‌ها، سفارش‌ها، مالی، شکایات و تخلفات، گزارش‌ها، تنظیمات
- **زنده از دیتابیس:** کاربران، نصاب‌ها، فروشگاه‌ها، داشبورد، Audit Log
- **عملیاتی:** تأیید «قرارداد و دریافت سفته حضوری» نصاب → وضعیت ACTIVE + Audit Log
- **عملیاتی:** تنظیمات پویا (کمیسیون ۱۵٪، سهم معرف ۵٪، بیعانه بازدید، گارانتی هر دسته، زمان‌بندی‌ها، BNPL، پلیس چت، شهرها)
- **سمت سرور:** گارد RBAC روی تمام `/api/admin/*` — پاسخ واقعی 401/403
- سفارش‌ها، مالی، شکایات و گزارش‌ها هنوز داده نمایشی برچسب‌دار دارند (تا ساخت سیستم سفارش)

## ۵) قوانین تجاری ثبت‌شده (خلاصه)

1. **صفر درصد هاردکد** — همه اعداد از `PlatformSettings` قابل ویرایش زنده از پنل
2. **سه روش قیمت‌گذاری + بیعانه اجباری بازدید حضوری** (ضد تبانی) — مدل آماده، ساخت سفارش در گام بعد
3. **ضمانت نصاب:** مراجعه حضوری + قرارداد فیزیکی + سفته با تیک ادمین
4. **قفل کد ملی:** الگوریتم ریاضی + جلوگیری از تکرار + هشدار ادمین
5. **BNPL:** برچسب «۴ قسط بدون چک و ضامن» — قابل خاموش/روشن
6. **پلیس خودکار چت:** سانسور شماره/آیدی تا قبل از پرداخت امانی (قاعده ثبت شد؛ اجرا با ساخت چت)

جزئیات کامل: `docs/ROADMAP.md` بخش ۰.

## ۹) امنیت

- هیچ کلید/توکن محرمانه‌ای در کد یا این مخزن قرار ندارد (ببینید `SECURITY.md`).
- اطلاعات حساس فقط از طریق **GitHub Secrets** به CI تزریق می‌شود.
- نشست با کوکی httpOnly؛ OTP مصرف‌شدنی با انقضا (در این فاز Sandbox با کد ثابت آزمایشی).
- RBAC سمت سرور روی تمام مسیرهای ادمین؛ Audit Log از نوع Append-Only.
- حساب‌های مدیریتی Sandbox (شماره‌های `0912000000x`) فقط برای محیط آزمایشی‌اند و
  سوییچر نمایشی با `NIROOKAR_DEMO_MODE=false` غیرفعال می‌شود.

## ۱۰) پیش‌نمایش زنده وب

نسخه وب روی مسیر `/` اجرا می‌شود. تمام نماها با ناوبری hash روی همین مسیر اجرا
می‌شوند و دکمه بازگشت مرورگر کار می‌کند. جریان پیشنهادی تست:

1. ورود مشتری: `#/login/customer` → شماره → کد `12345` → ثبت‌نام
2. ورود نصاب: `#/login/installer` → شماره دیگر → کد `12345` → ثبت پرونده (کد ملی معتبر + شبا + عکس)
3. ورود ادمین: فلش آزمایشگاهی (ابزار نمایشی) → «مدیر کل» → تأیید نصاب در «نصاب‌ها»
4. «تنظیمات»: تغییر درصد کمیسیون → ذخیره → بررسی Audit Log در داشبورد
